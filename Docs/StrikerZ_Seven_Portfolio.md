# StrikerZ Seven — 3D 카드 배틀 게임 개발 기록

> 7장의 패, 홀짝 TIME, 주사위 3개 중 1개 선택. 속성 상성으로 싸우는 3D 카드 배틀 게임.
> 기획 지시를 시간 순서대로 정리하고, 각 지시가 어떻게 구현되었는지 함께 기록한 포트폴리오입니다.

| 항목 | 내용 |
|---|---|
| 개발 기간 | 2026.09.29 ~ 2026.10.01 (3일) |
| 장르 | 1:1 턴제 3D 카드 배틀 (vs CPU) |
| 엔진 | Unity 6 (6000.3.18f1) · URP · UGUI(런타임 생성) · Input System |
| 역할 | 게임 기획 · 밸런스 기준 설계 · 아트/사운드 디렉션 · QA 피드백 |
| 구현 방식 | AI 페어 개발 (Claude Code + Unity MCP) |
| 에셋 제작 | VARCO 3D/Image(일러스트는 nano-banana-pro), VARCO Sound(BGM·효과음) |

## 개발 타임라인 (기획 지시 순서)

> 시간은 한국 시간(KST) 기준입니다. 각 항목은 **기획(지시 내용)** 과 **구현(결과)** 으로 나눴습니다.

### DAY 1 — 2026.09.29 · 코어 룰과 카드 체계

#### 1. 초기 기획서 전달 (10:14)
**기획**
- 3D 에셋 카드 게임, 가제 *StrikerZ Seven*
- 게임 시작 시 7장 드로우
- TIME 진행: 선공은 홀수 TIME, 후공은 짝수 TIME
- TIME마다 소환할 수 있는 몬스터가 정해짐
- 마법 발동 타이밍 t0 / t½. 예시 카드: 봉화, 포기란없다
- 앞면·뒷면 규칙, 개기일식
- 영웅(리더): 매치당 1회 능력, 능력에 따라 HP가 다름

**구현**
- 타이틀 → 영웅 선택 → CPU 대전 → 승패 → 재대결까지 전체 루프를 구현했습니다.
- VARCO 에셋
  - 3D: 게임 테이블, 주사위, 코인, 타이틀 엠블럼
  - 2D: 키아트, 로고, 카드 뒷면, 플레이매트, 영웅 초상화
- 카드는 데이터 한 줄(`CardData`)과 효과 조합(`Effects.*`)으로 추가할 수 있는 구조입니다.
- 필드 25종은 코드로 생성합니다.
- 양쪽을 AI가 플레이하는 **자동 대전 테스트**를 만들었습니다.
  - 빌드 전용 버그 2건을 이 테스트로 찾아 고쳤습니다: URP 셰이더 누락, FBX 내장 텍스처 미적용.
- 플레이 테스트 결과 TIME 5~6에 게임이 끝나 고TIME 카드가 나오지 못했습니다. 그래서 영웅 HP를 1.5배로 조정했습니다.

#### 2. 프레임 · 수치 분리 (11:42)
**기획:** 프레임 아트는 따로 뽑는다. 수치와 텍스트는 이미지에 굽지 말고 수정할 수 있게 한다. 몬스터와 마법은 카드마다 VARCO 개별 아트를 쓴다.

**구현**
- 타입별 프레임(몬스터·마법·영웅·필드)은 글자 없이 생성하고, 아트 창은 투명하게 뚫었습니다.
- 이름, ATK, 효과 텍스트는 데이터에서 실시간으로 렌더링합니다.
- 레이아웃은 `CardFrameLayout`에 0~1 비율로 정의해서, 프레임을 바꿔도 좌표만 맞추면 됩니다.
- 아트는 `Art/Cards/{카드id}.png` 이름 규칙을 따르므로, 새 카드는 코드 수정 없이 이미지만 넣으면 됩니다.

#### 3. 필드 카드 25종 개별 아트 (12:21)
**기획:** 필드 카드 25종도 개별 아트로 만든다.

**구현**
- 속성별 성역·폭주·결계 3종에 특수 필드 4종을 더했습니다.
- 전장 배경 콘셉트이므로 인물 없이 풍경만 그렸습니다.

#### 4. 영웅 오버프레임 (12:28 · 12:36)
**기획:** 영웅 아트는 유희왕 오버프레임처럼, 텍스트와 프레임 영역을 흐림 처리한다.

**구현**
- 일러스트가 카드 전체를 채웁니다.
- 프레임은 반투명(60%)입니다.
- 이름과 효과 영역은 같은 일러스트를 흐리게 깐 **프로스트 글라스 패널**로 만들었습니다.
- 처음에는 캐릭터가 프레임 밖으로 튀어나오는 방식으로 잘못 이해해서 만들었고, 피드백을 받아 수정했습니다. 이후 "오버프레임" 정의를 프로젝트 표준으로 고정했습니다.

#### 5. 신화 등급 마법 도입 (12:49)
**기획:** 레퍼런스 게임의 유니크 마법 중 적용할 수 있는 것을 변형해 **신화 등급**으로 넣는다. 일러스트는 항상 nano-banana-pro로 만든다.

**구현**
- 35장 중 우리 룰에 맞출 수 있는 12장을 골라 효과를 재설계했습니다.
- 새로 추가한 메커닉
  - t0 "상대 배틀 개시 시" 발동 타이밍
  - 행동 불능
  - 기간제 ATK 증감
  - 패·덱으로 되돌리기
  - 묘지 특수 소환(상대 카드는 소유권 획득)
- 생성된 일러스트에 다른 회사의 저작권 문구가 섞인 사례가 있어서 금지 조건을 넣어 재생성했습니다.

#### 6. 신화 카드 오버프레임 · 리네이밍 · 1장 제한 (13:19 → 14:10 재실행)
**기획:** 신화 카드도 오버프레임으로 하고, 이름을 비슷하지만 다르게 바꾸고, 신화는 1장만 쓸 수 있게 한다.

**구현**
- 레퍼런스와 겹치지 않도록 이름 12개를 바꿨습니다. 예: 저지먼트 → 저스티아, 기가윈드 → 테라 사이클론.
- 세로 풀아트 12장을 만들었습니다.
- 덱 제한 상수는 `MaxMythicPerDeck`입니다.
- VARCO 생성이 58%에서 멈춰서 중단을 보고했고, 지시를 받아 재실행해 완료했습니다.

#### 7. 주사위 시스템 개편 (14:59)
**기획:** 주사위를 3번 던져 3개 중 1개를 직접 고른다. 몬스터마다 1·2 / 3·4 / 5·6 구간 효과를 둔다(숫자와 무관).

**구현**
- 주사위 눈을 합산하지 않습니다. 고른 눈이 속한 **구간 효과**만 적용합니다.
- 효과 종류: ATK 증감, 상대 약화, 파괴 방지, 관통, 회복, 드로우, 영웅 피해
- 데이터는 `Dice.Of(a, b, c)` 체인 문법으로 정의합니다.

#### 8. 신화 몬스터 · 신화 마법 확장 (15:18)
**기획:** 레퍼런스의 이카젠 등급 몬스터(주사위·방어력 제거)와 마법을 신화로 넣는다. 덱당 신화 몬스터 1장, 신화 마법 1장으로 제한한다.

**구현**
- 신화 몬스터 12종과 신화 마법 8종을 이름과 디자인 모두 오리지널로 만들었습니다.
- 효과로 필드를 바꾸는 기능을 추가했습니다.
- 순속성 조건 카드는 랜덤 대전에서 잘 발동되지 않습니다. 그래서 조건을 강제로 맞춘 판을 만드는 **시나리오 테스트 프레임워크**를 만들었고, 16/16 통과했습니다.

#### 9. 주사위 밸런스 원칙 확립 (16:08)
**기획:** "효과 없음" 선택지를 없앤다. 세 구간은 **밸류는 같고 성격만 다른** 효과로 한다.

**구현**
- 효과마다 점수 가중치를 정했습니다.

  | 효과 | 점수 |
  |---|---|
  | ATK | 1 |
  | 파괴 방지 | 2 |
  | 관통 | 0.75 |
  | 회복 | 0.6 |
  | 드로우 | 1.5 |
  | 영웅 피해 | 0.8 |

- 한 몬스터 안의 구간 간 점수 차이는 최대 0.75 이내입니다.
- 32종 전체를 이 기준으로 다시 설계했습니다.
- AI는 상황에 따라 고릅니다. 이길 수 있으면 공격형, 질 것 같으면 파괴 방지, 방어 측은 공격 측의 선택을 보고 대응합니다.

#### 10. 메타 게임 — 마스터듀얼식 허브 (16:47 · 16:49)
**기획**
- 주사위 구간을 1·2 / 3·4 / 5·6으로 표시하고, 나온 눈만 활성화한다.
- HUD는 영웅 얼굴 대신 프로필을 보여준다.
- 마스터듀얼 같은 홈 화면과 상점을 만든다.
- 첫 부스터팩은 **SSS(START STRIKER SEVEN)**로 하고, 덱 편집을 넣는다.

**구현**
- 허브: 홈, 덱, 상점, 프로필
- 아바타 8종과 닉네임
- SSS 팩
  - 1팩 8장, 8번째 장은 SR 이상 확정
  - 등급별 확률표
  - ※ 이후 변경: 등급 개편(Common/Uncommon/Rare/Unique)과 함께 **1팩 7장, 모든 장 같은 확률, 확정 슬롯 없음**으로 바뀌었습니다. 현재 확률은 아래 [확률 공개](#확률-공개--sss-부스터팩)를 따릅니다.
- 덱 규칙: 장수 제한, 등급별 동명 카드 제한, 신화 제한
- 진행 데이터는 로컬 JSON에 저장합니다.

#### 11–12. 주사위 연출 피드백 반영 (17:31 · 17:52)
**기획:** 주사위 눈과 숫자가 다르다. 중앙의 3D 주사위는 유지하고, 효과 선택창만 TIME 아래로 옮긴다.

**구현**
- 원인을 분석했습니다. 생성된 주사위 텍스처에 1·2 면이 없고 7개짜리 면이 있었습니다.
- 원본 질감(흑요석, 금테)은 유지하고 표준 1~6 면 아틀라스를 다시 만들어, 면 방향이 정해진 큐브에 입혔습니다.
- 첫 수정은 기획 의도를 잘못 이해해 주사위 위치까지 바꿨습니다. 피드백을 받아 3D 주사위는 중앙으로 되돌리고 선택창만 옮겼습니다.

### DAY 2 — 2026.09.30 · 연출 · 사운드 · 수집 요소

#### 13. Unity MCP 연결 (09:39 · 09:41)
**기획:** 에디터 직접 연동 확인

**구현**
- 빠져 있던 브리지 패키지(`com.unity.ai.assistant`)를 설치했습니다.
- 이후 에디터를 직접 조작하고, 렌더링하고, 콘솔을 확인할 수 있게 되었습니다.

#### 14. 팩 개봉 연출 (09:52)
**기획:** 레퍼런스 쇼츠처럼 팩을 찢어서 카드를 꺼내고, 뒷면에서 앞면으로 뒤집으며, 레어일수록 빛나게 한다.

**구현**
- 연출 흐름

  | 단계 | 내용 |
  |---|---|
  | 1. 팩 등장 | 팩이 아래에서 올라옴 |
  | 2. 찢기 | 드래그로 절취선을 따라 찢음 |
  | 3. 꺼내기 | 카드 뭉치가 솟아오름 |
  | 4. 공개 | 낮은 등급부터 한 장씩 뒤집음 |
  | 5. 결과 | 그리드로 정렬 |

- 등급별 연출 6단계(N → 신화). 신화는 화면 암전, 광선, 이중 충격파, "MYTHIC!!!" 배너로 공개합니다.
- 찢기 전에도 오라 색으로 팩 안의 최고 등급을 암시합니다.

#### 15–16. 효과음 · BGM 1차 (10:19 · 10:44)
**기획:** 효과음과 BGM을 VARCO Sound로 만든 실제 사운드 파일로 교체한다.

**구현**
- 팩 효과음 18종과 게임 효과음 16종을 적용했습니다.
- 게스트 모드는 생성 횟수 제한(HTTP 429)과 클립 길이 제한(약 8초)이 있었습니다. 그래서 받은 음원을 레이어링해 고등급 공개음을 만들었습니다.

#### 17. 조작 · 설정 (11:10)
**기획:** 공격은 드래그 앤 드롭이나 단축키 1~7로 한다. 메인 메뉴에 키 설정과 환경설정을 넣는다.

**구현**
- 설정 탭
  - 사운드: 마스터, BGM, 효과음 볼륨, 음소거
  - 화면: 해상도, 프레임 제한, 수직 동기화
  - 게임: 연출 속도
  - 키 설정: 11개 동작 리바인딩, 이미 쓰는 키는 서로 맞바꿈

#### 18. 정식 BGM · 효과음 (11:47)
**기획:** (VARCO 로그인 후) BGM과 나머지 효과음을 다시 생성한다.

**구현**
- 메뉴·전투 BGM은 각 2곡이고 길이는 2분 24초~3분 33초입니다. 끝 4초를 시작과 크로스페이드해 끊김 없이 루프합니다.
- 전용 효과음 7종을 다시 생성했습니다: 승리, 패배, 방어, 피격, 필드, 드로우, 영웅.

#### 19. 카드 가공(Finish) 시스템 (12:44)
**기획**
- 모든 카드에 팩 개봉 시 확률로 가공을 붙인다.
  - **Seven(10%)**: 은색 테두리, 은빛 이름 반짝임, 10초 페이드인 광채
  - **StrikerZ(1%)**: 금색
- 팩 개봉 BGM과 레어 전용 BGM·효과음을 만든다.

**구현**
- 가공은 보유 장수와 별도로 기록됩니다.
- 대전에서는 보유한 가공 중 좋은 것부터 자동으로 장착합니다.
- 금속 그라데이션 이름, 반사광, 반짝이 입자를 넣었습니다.
- 팩 개봉 시 가공 카드는 전용 기 모으기, 배너, 효과음이 나옵니다. StrikerZ는 신화급 강도로 연출합니다.

| ◆ Seven | 10% |
| ★ StrikerZ | 1% |

- 특정 카드의 특정 가공 확률 = 카드 1종 확률 × 가공 확률. 예: Unique 카드 1종이 StrikerZ로 나올 확률 = 0.0312% × 1% ≈ 0.0003% (카드 1장 기준).
- 수록 카드가 바뀌면 카드 1종 확률도 바뀝니다. 게임 안 [확률 정보] 표는 실행할 때마다 다시 계산되고, 이 문서의 표는 위 수치(수록 339종 기준)로 갱신해야 합니다.
- 확률표에 확률이 있는데 수록 카드가 없는 등급이 생기면(실제와 공개 확률이 달라지는 상황) 게임 시작 시 오류를 남기고, 자동 테스트가 오류로 잡습니다.

## 에셋 제작 파이프라인

| 에셋 | 도구 | 방법 |
|---|---|---|
| 카드 일러스트 | VARCO Image (nano-banana-pro) | 개별 생성, 오버프레임은 기존 아트를 레퍼런스로 세로 풀아트 생성. 대량 몬스터는 2×2 그리드 생성 후 자동 크롭 |
| 카드 프레임 | VARCO Image + Python(Pillow) | 생성 → 여백·창 투명화(BFS 영역 확장) → 레이아웃 좌표 보정 |
| 3D 영웅 | VARCO 3D | 이미지 → 메시 → 휴머노이드 리깅 → 애니메이션 → Unity 프리팹 자동 빌드(에디터 메뉴) |
| BGM · 효과음 | VARCO Sound | 후보 여러 개 생성 → 파형·음정 분석으로 선택 → ffmpeg 정규화·루프 크로스페이드 → OGG |
| 데이터 | Python 생성기 | 몬스터 표 → `MonsterSet.cs` 자동 생성 |

### 데이터 · 아트 분리 구조
- 카드 수치와 텍스트는 코드 데이터에 있습니다. 아트는 `{id}.png`, 오버프레임 아트는 `{id}_full.png` 이름 규칙으로 자동 연결됩니다.
- 프레임 좌표는 `CardFrameLayout`에서 비율로 관리합니다. 아트를 교체해도 코드는 바뀌지 않습니다.

## 품질 검증 체계

- **AI 자동 대전**: 실행 인자 `-strikerz-autotest`. 양쪽을 AI가 끝까지 플레이하고 로그와 스크린샷을 남깁니다.
- **시나리오 테스트**: 실행 인자 `-strikerz-scenario`. 발동 조건을 강제로 맞춘 판을 만들어 카드와 규칙을 하나씩 검증합니다. 수는 16개 → 21개 → 26개 → 43개로 늘었습니다.
- **연출 갤러리 테스트**: 실제 카드를 발동시키는 도중 스크린샷을 찍어 검증합니다.
- **빌드 검증**: 기능을 바꿀 때마다 독립 Windows 빌드를 만들어 확인합니다. 에디터 전용으로는 드러나지 않는 버그(셰이더 누락, 텍스처 누락)를 이 단계에서 찾았습니다.

## 회고 — 기획 커뮤니케이션에서 얻은 것

- **정의가 모호한 용어는 바로 표준으로 고정했습니다.** 처음에 '오버프레임'을 잘못 해석한 뒤, 정의를 문서화해 이후 영웅·신화 카드 작업에서는 같은 문제가 반복되지 않았습니다.
- **밸런스는 "기준"으로 지시했습니다.** 숫자를 하나씩 정하지 않고 원칙을 전달했습니다(주사위 구간 동일 밸류, 속성별 T1 기준, 상성 순환). 그래서 270종을 생성기로 일관되게 만들 수 있었습니다.
- **피드백 루프를 빠르게 돌렸습니다.** 지시 → 빌드 → 스크린샷·로그 보고 → 수정 지시로 한 사이클이 짧습니다. 3일 동안 지시 33건을 반영했습니다.
- **AI 생성 에셋을 검수했습니다.** 저작권 문구, 실물 카드 테두리, 종교적 도상, 주사위 면 오류처럼 생성물의 결함을 잡아 재생성하거나 대체했습니다.
